# 32bit実用環境

配布するMS-DOSのソースは `scripts/prepare-msdos4-cpanel-ci.sh` の完全コミットIDで固定する。HDD単独起動、完全FD、アプリをHDDへ分離したFD構成で同じネイティブ実装を使用する。

1. **実行資源とSDK**：ABI 258は `K32RES01` に4–256 KiBのスタックと最小ヒープを宣言する。従来の4 MiB仮想空間内にガードページを置く。最小Cライブラリ、雛形、ハッシュ照合付きシンボル診断、実CPUで境界を検査する `PRACT32.EXE` を含む。
2. **共通Work I/O**：`K32IO.EXE` と機能ビット256で、GUIに依存しないバイナリ入出力を提供する。対象はWork内の限定8.3名、最大1 MiB、1回4096バイト。所有者別ハンドル、リビジョン確認、TMP/BAK保存、未使用名への明示復旧を使う。終了や失敗ではハンドルを閉じ、未完了TMPと原本を保持する。電源断に対する原子的な保存や、不変の読込スナップショットは保証しない。
3. **画像SDK**：384×256の主サーフェスと128×128の追加サーフェスを各アプリが所有する。64行ずつ画面を転送し、デスクトップは4 MiBのまま、32 MiB構成で4アプリを動かす。ImagesはBMP 8/16/24/32bitの限定デコード、BMP24保存、50/100/200/400%ズーム、原画像プレビュー、Undoを備える。ズームは操作パネル内へクリップする。
4. **共通IME**：Editorとユーザー辞書アプリ `KGWORDS.EXE` が同じ入力・確定APIを使用する。原作辞書1076読み、限定的な語結合・助詞・活用形、ユーザー語優先に対応する。Workの `USERIME.DIC` は最大256読み・32 KiB、保存とEditorのF9再読込は明示操作。競合時は原本と私有編集を保持し、検証済みTMP/BAKは未使用の `RECIME.DIC` へ復旧する。

## 検証

ローカルではネイティブ単体試験、Web単体試験とビルドを行う。ブラウザ試験とpreviewはGitHub Actionsでのみ実行する。`practical32.yml` はPEGC/Cirrus双方の5系統で、実CPL3とPTE・ガード例外、単独K32RUN、70 KiBバイナリ保存と再起動、ディスク満杯、4画像所有者とCanvas画素、辞書競合・復旧・再起動を検証する。4本の最大画像・第4枠編集・他枠の進行と回収は32 MiBの専用ジョブで検査し、ズーム・形式・保存・再起動は16 MiBの専用ジョブで検査する。重い編集では実際のフレーム公開を待機する。RAMを書き換えて成功状態を作らず、起動前のディスクfixtureと実際の入力だけを使用する。

## 次の開発単位

- プロセスのspawn/wait、IPC、標準入出力のリダイレクトとパイプ、32bitシェル。
- DOS BIOS・描画互換性（GRCG/EGC/PEGC/SVGA、word I/O、複数ページ）。パーティション拡張とDOS FEPは別単位で扱う。
- 4 MiBを超えるアプリ空間、追加画像形式、IMEの予測・学習は今回の限定実装から分けて設計する。
