# 32bit実用環境

配布するMS-DOSのソースは `scripts/prepare-msdos4-cpanel-ci.sh` の完全コミットIDで固定する。HDD単独起動、完全FD、アプリをHDDへ分離したFD構成で同じネイティブ実装を使用する。

1. **実行資源とSDK**：ABI 258は `K32RES01` に4–256 KiBのスタックと最小ヒープを宣言する。従来の4 MiB仮想空間内にガードページを置く。最小Cライブラリ、雛形、ハッシュ照合付きシンボル診断、実CPUで境界を検査する `PRACT32.EXE` を含む。
2. **共通Work I/O**：`K32IO.EXE` と機能ビット256で、GUIに依存しないバイナリ入出力を提供する。対象はWork内の限定8.3名、最大1 MiB、1回4096バイト。所有者別ハンドル、リビジョン確認、TMP/BAK保存、未使用名への明示復旧を使う。終了や失敗ではハンドルを閉じ、未完了TMPと原本を保持する。電源断に対する原子的な保存や、不変の読込スナップショットは保証しない。
3. **画像SDK**：384×256の主サーフェスと128×128の追加サーフェスを各アプリが所有する。64行ずつ画面を転送し、デスクトップは4 MiBのまま、32 MiB構成で4アプリを動かす。ImagesはBMP 8/16/24/32bitの限定デコード、BMP24保存、50/100/200/400%ズーム、原画像プレビュー、Undoを備える。ズームは操作パネル内へクリップする。
4. **共通IME**：Editorとユーザー辞書アプリ `KGWORDS.EXE` が同じ入力・確定APIを使用する。原作辞書1076読み、限定的な語結合・助詞・活用形、ユーザー語優先に対応する。Workの `USERIME.DIC` は最大256読み・32 KiB、保存とEditorのF9再読込は明示操作。競合時は原本と私有編集を保持し、検証済みTMP/BAKは未使用の `RECIME.DIC` へ復旧する。

5. **カレンダーとタップ操作**：`KGCAL.EXE` はDOS日付を読み、1980–2099年の月表示、前月・翌月・年移動・Todayを提供する。タイトルバーから最大化、左右整列、元の位置と寸法への復元ができる。ClockとCalendarのメニューは選択状態や無効な操作を表示する。シェルの入力欄にはEnterとEsc、実行時にはCancelとEOFを表示する。[ネイティブ操作ガイド](https://github.com/kumakumapon/MS-DOS/blob/main/tools/kgui32/APPS-AND-TOUCH.md)

## 検証

ローカルではネイティブ単体試験、Web単体試験とビルドを行う。ブラウザ試験とpreviewはGitHub Actionsでのみ実行する。`ci.yml` のpractical32行列はPEGC/Cirrus双方の10系統で、実CPL3とPTE・ガード例外、単独K32RUN、70 KiBバイナリ保存と再起動、ディスク満杯、4画像所有者とCanvas画素、辞書競合・復旧・再起動を検証する。4本の最大画像・第4枠編集・他枠の進行と回収は32 MiBの専用ジョブで検査し、ズーム・形式・保存・再起動は16 MiBの専用ジョブで検査する。重い編集では実際のフレーム公開を待機する。RAMを書き換えて成功状態を作らず、起動前のディスクfixtureと実際の入力だけを使用する。

## 次の開発単位

- 簡易表計算とFilesからの起動、スマホでの表示倍率とタップ範囲の調整。
- 複数ジョブ、stderrのリダイレクト、名前付きIPC。
- DOS描画の機種別互換性（GRCG/EGC/PEGC/SVGA、追加BIOSモード）。パーティション拡張とDOS FEPは別単位で扱う。
- 4 MiBを超えるアプリ空間、追加画像形式、IMEの予測・学習は今回の限定実装から分けて設計する。

## プロセス・DOS互換・転送性能

`K32PROC.EXE` はGUIと独立したプロセスサービスを提供する。機能ビット512を明示したABI 258アプリは、8.3 EXEの起動、親だけが可能な待機・終了コード取得・取消し、64バイト×4件のIPC（親子間と受信側が許可した生存中の独立送信者1件）、512バイト×4本の非同期パイプを使える。ルート4記録と子4記録を予約し、実行枠は16 MiBで2、32 MiBで4。世代・物理領域・epochを照合し、親終了・例外・Endで子と端点を回収する。DOS操作はHOSTコールバック外の明示pumpで行う。`KPRUN.COM` はGUIを終了した実DOSから同じシェルとストリームを実行する。

F2の「32-bit shell」は `KSH32.EXE` を起動する。外部コマンド3個までのパイプ（シェルを含む4実行枠が必要）、Work内の `<IN.TXT >OUT.TXT`、引用符、126文字のコマンド、最大1 MiB出力に対応する。Ctrl+D／EOFは標準入力の終端、Ctrl+C／Cancelは前景の取消し。`bg`、`jobs`、`cancel`で子ジョブ1件を管理できる。`KTOOL32.EXE wc` は行・単語・バイト数を集計する。アプリの診断出力は私有コンソールに表示する。保存は全子の正常終了と出力EOF後にリビジョンを照合して共通TMP/BAK処理を使う。失敗・競合・満杯では原本を保持する。継承ストリーム非対応の旧アプリへのリダイレクトは拒否する。完全FDは容量確保のためMEM32診断だけを省き、HDDと元のK386媒体には保持する。

DOS端末は私有128 KiB×2ページと独立したA6アクセス/A4表示、限定INT18のテキスト・グラフィック・カーソル・キュー操作、INT21h/AH=0Chの私有キュー消去と入力、GDC低位バイトで終端するword IN/OUTに対応する。V86のbackingは928 KiBのまま、私有フォントと描画面を重ならない未使用領域へ配置する。未対応BIOSモードはCFとエラーを返し、未対応dword I/Oは当該所有者だけを例外終了する。`KVEXT.COM` が実V86命令で検証する。GRCG/EGC/PEGC/SVGAのハードウェア互換は今後の範囲。

画像要求の3144バイトABIと全範囲検証は保持し、status/controlは72バイトのヘッダを転送する。成功status往復は6288→144バイト、upload往復は6288→3216バイト。所有者のメタデータだけを更新し、RAMコピーはdwordと正確な端数を使用する。`KGXFER01` の実測値と、4所有者の全画素・Canvas・他枠の進行・回収をActionsで確認する。経過時間は記録し、ホスト速度による不安定なしきい値にはしない。

プロセス常駐サービスと4枠を同時に使えるよう、GUIの画面転送用一時バッファを32→28 KiBへ縮小する。転送行数は実ピッチと確保量から求め、最大RGB565行が収まることを静的検査する。スタックガードとXMS予算は保持する。
