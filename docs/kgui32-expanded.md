# 実行枠・メモリ拡張

起動画面の「KGUI32（32MiB・アプリ4枠）」を選ぶと、独立したGUIとは別に
DOS／PM32アプリを4本まで実行できます。PEGCとCirrusの両方を選べます。
既存の16MiB・2枠の起動選択と完全版FDも引き続き利用できます。

上部のDOS 1～4で各枠のウィンドウを開き、Runでコマンドを指定します。
4つのタスクバー、Systemの状態表示、入力・停止・再開・終了・再起動を枠ごとに使えます。
Calculator・Clock・Files・Editorも同じ4枠を利用します。
SystemのTest CPUは利用可能な全枠に診断アプリを起動します。

32MiBは全体のメモリ構成です。PM32の各アプリは従来と同じ4MiBの私有領域を持ちます。
GUI専用の4MiB、各枠のページテーブル・XMS・ファイルハンドルを分離します。
24MiB以下で起動した場合は2枠となり、拡張要求の失敗で状態を変更しません。
終了時はGUIが所有する世代のアプリと、今回確保した追加枠の管理領域を回収します。

ネイティブのD392／K32MUX02で容量と4枠の実際の状態を公開します。
従来D391／K32MUX01、D390／K32HOST1、V86の固定レコードとサイズを維持しています。
GUI_SESSION／GUI_SNAPSHOT／描画クライアントの所有者・世代検証は追加枠にも適用します。
詳細は[ネイティブ仕様](https://github.com/kumakumapon/MS-DOS/blob/main/tools/kgui32/CAPACITY.md)。

CIはPEGC／Cirrusで、配布HDDから4本のCPL3アプリ・4本のDOS・混在実行・GUIアプリ4本を
実行します。実CPUフレーム、実ページテーブル、異なる私有メモリと世代、継続進行、
停止・再開、例外と枠の再利用、24MiBでの拒否、FD起動、終了時の通常／拡張メモリ回収、
割り込みベクタ復旧と媒体全体の不変性を検証します。
ブラウザE2EとプレビューサーバーはGitHub Actions内で実行します。
