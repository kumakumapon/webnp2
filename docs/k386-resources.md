# K386の資源管理

MS-DOS #19 / webnp2 #19では、現代のOSの資源管理を参考に、ゲスト側の
優先度付きスケジューラ、CPU時間上限、資源情報、障害履歴、中断操作を追加します。
既存の独立V86実行を利用し、HTMLやブラウザタイマーでDOSを並行実行させる方式ではありません。

実験版KDESK/386で起動し、Ctrl+N / Ctrl+OでDOSウィンドウ、Ctrl+TでTasksを開きます。
DOS 1 / DOS 2を矢印またはマウスで選ぶと、現在のプログラム、起動ID、優先度、
実行時間、実行回数、XMS・ヒープ使用量、ハンドル数、EXEC段数、停止・障害理由を表示します。

| 操作 | 動作 |
| --- | --- |
| P / Prio | Normal → High → Low。実行比率の重みは2 / 4 / 1 |
| L / Limit | CPU上限を無制限 → 1000 → 5000 → 10000ms → 無制限 |
| S / Stop | セッションを停止 |
| R / Start | 再開。終了・障害後は新しいKSHを起動 |
| K / End | 全EXEC段を終了し、XMSとハンドルを解放 |
| B / Break | 現在のプログラムを中断。親があれば親へ復帰 |
| DOS内のCtrl+C | Breakと同じ中断 |
| [ / ] | 最大16件の履歴を前後に移動 |

CPU上限は起動後の累積実行時間に適用され、残り時間ではありません。上限到達時は
メモリ・レジスタ・画面・ハンドルを保持して停止します。上限を拡張または解除し、
明示的にStartすると続きから動作します。他のDOSセッションとGUIは動き続けます。
優先度と上限の設定はスロットに残り、ルートプログラムの再起動で使用量と起動IDを更新します。
子EXECは親と同じセッションの予算を消費します。

時間はPC-98のARTICカウンター（307200 ticks/s）で測るエミュレータ内の実行・DOSサービス時間です。
GUIの待機時間や初期ロードは含みません。ブラウザCPU使用率を示す数値ではありません。
上限の判定はCPU実行区間の終了時で、1区間とDOSサービス分の超過があり得ます。
PITによるプリエンプションを維持し、CLIループも制御します。

中断はモニターが現在のプログラムを終了させる操作で、POSIXシグナルやDOS INT 23hの配信ではありません。
EXECの親にはAH=4Dhで0103hを返し、親のメモリ・CPU・ファイル状態へ復帰します。
ルートの中断ではそのプログラムを終了します。Endとは別の操作です。

実装はMS-DOSの `tools/k386/resources.c`、`report.c`、`monitor.c` とKDESKクライアントに分離しています。
元の4240バイトのK386ABI1は維持し、INT 2Fh AX=D387hでK386SYS1（v1、1084バイト）を発見します。
旧モニター・通常KDESKへフォールバックでき、既存DOSカーネルとNP2kaiコアを変更しません。
詳しいABIと計測範囲はMS-DOSの `tools/k386/RESOURCES.md` に記載しています。

`scripts/prepare-msdos4-cpanel-ci.sh` がネイティブ実装の完全SHAを固定し、通常版と実験版の
両方を生成します。実験版には操作説明と実DOS用のKRESCHK.COM / INTWAIT.EXEを同梱します。
`scripts/verify-k386-resources.mjs` は実CPU・ページテーブル・CPU時間・私有RAM・画面・
親復帰・資源解放をPlaywrightで検査し、ディスク全体のSHA-256が変わらないことも確認します。
既存の通常GUI・K386基盤・シェル・プロセスのCIも維持します。

汎用DOS/BIOS/TSR互換、ゲストXMS/EMS API、共有ディスクへの書き込み、外部グラフィックの
完全な仮想化は未完成です。この追加をそれらの完成として扱いません。
