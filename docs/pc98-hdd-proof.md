# DOS4 PC-98 HDD認識・基本I/Oの技術検証

既存のDOS4 FDから起動し、専用の40MB THDをDOSの追加ドライブとして使う
検証プロファイルです。通常のKDESK/KGUI32起動イメージは変更しません。
KGUI32の保存先変更・アプリ配置・HDD単独起動は次段階です。

## ビルドと起動

```sh
bash scripts/prepare-pc98-hdd-ci.sh
npm ci
npm run dev -- --host 127.0.0.1 --port 4173
```

`public/hdd-proof/manifest.json` の `fd.image` と `hdd.image` を指定します。

```text
http://127.0.0.1:4173/?fd1=./hdd-proof/<fd.image>&hdd=./hdd-proof/<hdd.image>&run=1&mem=16&clk=8&worklet=0
```

Cirrusでは `&video=cirrus` を追加できます。Pages配信時も `/webnp2/` 以下の
同じ相対パスを使います。生成物は専用ディレクトリに配置し、40MBのバイナリを
Gitには追加しません。manifestにはソースコミット・FD/HDDのSHA256を記録します。
既存の通常プロファイルは従来のソース固定を維持します。

成功時は `HDD DRIVE=B BPS=1024 SPC=4 CLUSTERS=10116`、
`BYTES=41435136`、`READ PASS` と表示されます。B:はこの構成でDOSが割り当てる
ドライブ文字です。CONFIG.SYSから `KHD98.SYS` を読み込み、FAT管理はDOSが行います。

## データの扱い

専用の新規ディスクだけを使ってください。`KHDPROOF` パーティション・BPBの
識別子と正確なジオメトリを持たないHDDはドライバが登録を拒否します。
ドライバは既存ディスクのフォーマットや修復を行いません。

`HDDTEST W` は予約テストファイル `B:\IOPROOF.DAT` に131073バイトを書き込み、
`HDDTEST V` で照合します。`HDDTEST O` で異なる内容に上書きし、
`HDDTEST T` で照合します。**このファイルは上書きされます。**
`HDDTEST B` は境界・64KiB跨ぎ・書込照合・BIOS部分失敗の診断です。
同じHDDを複数の起動中エミュレータで同時に書き込まないでください。

WebNP2のHDDダウンロードで変更済みTHDを保存できます。新しいブラウザ起動で
そのTHDと検証用FDを指定し、`HDDTEST T` で再読込を確認できます。
URLから同じ名前を再読み込みした場合はIndexedDBの保存済みディスクが使われる
ことがあります。配布元の新規ディスクと保存済みディスクを区別してください。

## 実装上の判断

NP2kaiの既存PC-98 INT 1Bh LBA I/Oを利用します。CPU/BIOSコア変更はありません。
THDの物理セクタは256バイト、DOS向け論理セクタは1024バイトです。
現在のDOS4 OEM初期化で最大セクタサイズがFD由来の1024バイトになるため、
既存の2048バイト論理セクタの汎用HDD生成器を流用しません。
カーネルのオリジナルソースを変更せず、追加ドライバで検証します。

615×8×33の物理ジオメトリ、先頭シリンダ予約、FAT16・4セクタ/クラスタで
データ容量は41,435,136バイトです。初期マーカーファイルが1クラスタ使います。
ドライバは2KiB整列のバウンスバッファ、論理範囲・通常メモリ範囲チェック、
完了セクタ数付きエラーを実装します。詳細はMS-DOS側の
`ports/pc98/hdd/README.md` とソースを参照してください。

## 自動検証

```sh
WEBNP2_NO_SANDBOX=1 CHROMIUM=/usr/bin/chromium \
  node scripts/verify-pc98-hdd.mjs http://127.0.0.1:4173/ test-results/hdd-proof
```

実DOSの容量照会・ファイル読み書き・異なるパターンでの上書き・64KiBを超える
ファイル・新規ブラウザでの再起動後照合を行います。ダウンロードしたTHDの
FAT16を独立して解析し、2つのFAT・クラスタ鎖・ファイル内容・孤立割当を検査します。
FD、IPL、パーティション、BPB、マーカーファイル、末尾領域の保持も照合します。

診断レコードの実I/Oカウンタ、入力バッファの64KiB跨ぎ、範囲外リクエスト拒否、
一時的なINT 1Bh故障注入による部分完了とベクタ復元を検査します。
HDDなし・別識別子・非対応BPB・末尾切詰めも起動し、ドライブを登録せず、
ディスクを変更しないことを確認します。ゲスト起動中にホストのFAT APIで
ディスクを書き換える操作はしません。結果・スクリーンショット・保存済みTHDは
指定した出力ディレクトリに残します。
