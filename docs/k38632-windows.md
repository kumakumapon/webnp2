# KDESKのPM32ウィンドウ

実験用の **KDESK/386 (experimental)** を選ぶと、16 MiBの拡張メモリで
K386 → K32HOST → KDESKが起動します。共有スロットは2つで、PM32同士、
PM32とV86、V86同士の組み合わせで実行できます。GUIと実行管理はPC-98
ゲスト内にあり、ブラウザ側にアプリのウィンドウを作る方式ではありません。

## 操作

Ctrl+Kのアプリ検索から次を起動します。空いているスロットを使います。

| 検索名 | 実行内容 |
| --- | --- |
| PM32 viewer | `VIEW32.EXE VIEWDATA.TXT`：読み取り専用テキスト表示 |
| PM32 ticker | `COUNT32.EXE 1`：私有ヒープを検査しながらカウント |
| PM32 memory test | `MEM32.EXE`：メモリ検証 |

Ctrl+N / Ctrl+Oは1番・2番のウィンドウにフォーカスします。Ctrl+Eで終了し、
Ctrl+Lで `COUNT32.EXE 2`、`VIEW32.EXE VIEWDATA.TXT`、`KSH.EXE` などを指定できます。
実行中のPM32を置き換える場合は先にEndしてください。通常のウィンドウと同じ
移動、サイズ変更、左右配置、最大化、最小化、復元、タスクバー切り替えが使えます。
サイズ変更は固定80×25コンソールに対する表示範囲の変更です。

入力はフォーカスしたウィンドウだけに届きます。停止中の入力はキューに保持し、
Escapeを含め再開後に処理します。停止中も即座に解放するにはEndを使います。VIEW32はn/p、j/k、
PageDown/PageUp、Home/End、qで操作します。Escapeは選択したPM32を終了します。
Ctrl+Pは停止、Ctrl+Rは同じCPU・メモリ状態から再開、Ctrl+Eは終了です。
Ctrl+TのTasksでは優先度、CPU時間制限、世代ID、XMS、ヒープ、ファイル数と
履歴を確認できます。終了・例外・End後のR/Startは元のPM32コマンドを再起動し、
新しい世代IDを割り当てます。停止中のR/Startは再開します。

別のアプリにフォーカスしてもバックグラウンドの処理は進みます。電卓、時計、
メモなど既存の内部アプリも併用できます。待機中はユーザーコードを再実行せず、
入力・期限を確認します。停止中はメモリとハンドルを保持し、終了・例外時は
その所有者だけの資源を回収します。最後の画面と診断記録は再利用まで残ります。

## 実装と制限

K32HOST.EXEは独立したリアルモード常駐サービスです。PM32の各スライスで
Ring 3とページングを実際に使い、IRQ0またはシステムコールでリアルモードに
戻ります。共通マネージャK32MUX01が既存V86とPM32を選択し、実行量と履歴を
管理します。CPUフレーム、スタック、ページテーブルと入力・画面は分離しています。
従来のK386ABI1とPM32 ABI 0100h/0101hは維持します。K32HOSTがなければ従来の
V86管理へ、K386もなければ通常KDESKへフォールバックします。

PM32は1アプリ4 MiBで、コード・起動情報・スタック・ヒープがこの範囲を共有します。
XMS予約はアライメント分を含む4100 KiBです。通常メモリにも常駐64 KiBと
各タスクの管理領域・ページテーブルが必要です。画像バッファなどの空き容量は
少なくなります。PM32ファイルAPIはASCII 8.3形式のA:ルート通常ファイルのみ、
読み取り専用・最大8ファイルです。DOS呼び出しはリアルモードで直列化します。
共有ディスクへの書き込みは許可していません。

一般的なDOS/BIOS/TSR互換、Windows/DPMI互換、PM32のGUI部品API、x87/SIMD、
3つ以上の実行スロット、可変サイズのコンソール、外部GDC/PEGCアプリの同時描画は
未対応です。全画面の通常DOS EXEC中はGUI駆動のスケジュールも停止します。重なったウィンドウなど重いGUI再描画中は
タスクの実行量も低下します。
遅い同期DOS読み取りは10 msのバッチ目標を超えることがあり、その復帰後に
次のスライスを開始しない設計です。

## ビルドと検証

`scripts/prepare-msdos4-cpanel-ci.sh` がMS-DOSの完全なコミットSHAを固定し、
通常・実験用イメージを同じソースから生成します。実験用KDESKもそのソースから
再ビルドします。マニフェストはSHA、作業ツリー変更の有無、イメージのハッシュを
保持します。生成イメージはCI成果物で、既存の保存ディスクを書き換えません。

```sh
bash scripts/prepare-msdos4-cpanel-ci.sh
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 4173 --base /webnp2/
CHROMIUM=/usr/bin/chromium WEBNP2_NO_SANDBOX=1 \
  node scripts/verify-k38632-windows.mjs http://127.0.0.1:4173/webnp2/ test-results/pm32-pegc pegc
# 最後の引数をcirrusにするとRGB565モードを検証
```

新しいCIはPEGC/Cirrusの両方で実CPUフレーム、異なるCR3・物理ページ、同じ
仮想アドレスの私有データ、バックグラウンド進行、入力分離、待機・停止再開、
再起動世代、#PF/#GPの局所回収、V86混在、16個の実DOSハンドルを確認します。
GUI終了後の通常メモリ/XMS回収、実際の4 MiB不足時に元のV86所有者を維持すること、
ディスク全体のSHA-256不変性も検査します。JSON記録と画面はCI成果物に保存します。
従来のPM32単独実行、V86、GUI、XMS、XARRAYの回帰ジョブも継続します。

依存関係はMS-DOS #36 → MS-DOS mainのCI成功 → webnp2 #36の順です。
全体ロードマップのMS-DOS #31は継続します。正確な検証結果は各PRとそのCIに記録します。
ネイティブ側の詳細設計は `tools/k38632/HOST.md` を参照してください。
