# Work復旧とEditor操作性の開発契約

MS-DOS #31 第4b段階の復旧UI・限定API・webnp2 E2Eと、検索・置換、Shift選択、
LF/CRLF選択、表示領域拡大を連携して実装します。両リポジトリでドラフトPRを作り、
受入とCIを確認してからレビュー可能にします。マージは自動実行しません。

復旧対象はゲスト仲介層が選ぶWorkに限定します。TXT/TMP/BAKの状態・内容を確認し、
利用者が候補と空いている8.3 TXT名を選んで復旧します。候補の内容はDOS renameで
新しいTXT名へ移し、既存TXTや他の候補を上書き・自動削除しません。世代・revision、
保護属性、名前と所有権を検査し、失敗時は原本を保持します。任意パス・ドライブ、
汎用削除・rename、媒体初期化は提供しません。電源断時のFAT原子性とは区別します。

Editorでは検索・取消で本文を変更せず、全置換を一回のUndoで戻せるようにします。
Shift修飾キーは明示購読したクライアントへ配送し、既存のwireサイズと入力契約を
維持します。改行形式は読み込み・dirty・Undo/Redo・保存に反映し、CRLF変換後の
64 KiB上限と実保存バイトのrevisionを確認します。拡大表示は40描画命令の枠内です。

ネイティブのポリシー・異常系テスト、PEGC/Cirrusでの実CPL3、Work復旧、保存・
再読込・コールドブート、検索置換・Shift選択・改行・表示拡大、媒体保護・全資源回収を
確認します。既存回帰を維持し、webnp2へcleanなnativeコミットを固定します。
このチャットでnpm run previewを起動しません。ブラウザE2EはGitHub Actionsで実行します。
