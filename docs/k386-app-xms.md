# KDESK/386 アプリ向けXMSデータAPI

K386用の16ビットEXEから、64 KiBを超えるデータをXMSに保持できます。
コード・スタック・通常のポインタは従来の16ビットSDKのままです。
大きなデータはハンドルと32ビットのオフセットで管理し、必要な部分を通常メモリへ転送します。
組み込みGUIアプリの文書・画像サイズは今回変更していません。

- セッションごとに最大 **4 MiB、8ブロック**。子プロセスとも容量を共有します。
- 1ブロックは1～4096 KiB。実際の確保には空きXMSが必要です。
- 1回の読み書きは最大4 KiB。64 KiBを超える位置も指定できます。
- セッションとPSPで所有権を確認し、他セッション・親子間の無断アクセスを拒否します。
- 新規領域は全バイトをゼロ初期化してからアプリへ渡します。
- 通常終了・保護例外・割り込み終了・セッション終了・実行プログラムの置換で自動解放します。
  停止・CPU制限による一時停止では保持します。
- 初期化は1回のスケジューラ処理で最大16 KiBずつ進め、GUIと別セッションへ実行機会を返します。
- タスクマネージャのXMS使用量に、VM自体の664 KiBとアプリの確保量を合算して表示します。

開発側ではMS-DOSの `tools/k386/sdk.h` にある `kapp_xms_alloc`、
`kapp_xms_read`、`kapp_xms_write`、`kapp_xms_free`、`kapp_xms_usage` を利用します。
最初に `kapp_xms_version()==0x0100` を確認してください。関数は成功時0、失敗時にエラーを返します。
所有権付きハンドルは直接参照できず、解放後の番号も再利用しません。
1回の起動で65535回の確保に達した場合は、再起動まで新規確保を拒否します。

同梱の `XMEM.EXE` は1 MiB全体の初期値・書き込み・読み戻し、64 KiB境界、
奇数長、末尾バイト、範囲外アクセスを実際のXMSドライバで検証します。
DOSウィンドウでCtrl+Lを押して `XMEM.EXE` を指定するか、Filesから起動できます。
準備完了後はQで終了、Fで保護例外、Pで子プロセスの所有権検証、Tで他ハンドル拒否、
Rで保持データの再検証を行います。Fはこの診断アプリだけを異常終了させます。
`XCHILD.EXE` はPから呼ばれる所有権検証用アプリです。

この追加は32ビットEXE実行環境やDPMIではありません。既存のDOS/BIOS対応範囲と
セッション側ディスク読み取り専用制限は継続します。一般のDOSアプリがXMSドライバを
直接呼ぶ互換APIも追加していません。API仕様と設計はMS-DOSの `tools/k386/XMS.md` を参照してください。

ビルドは `scripts/prepare-msdos4-cpanel-ci.sh` の固定MS-DOSコミットから行います。
生成された拡張イメージを `npm run build` で配信し、
`node scripts/verify-k386-xms.mjs http://127.0.0.1:4173/webnp2/ test-results/k386-xms`
で実CPU・XMS割り当て記録・セッション別画面・ディスク不変性を検査します。
CIにも独立した `k386-xms` ジョブを追加しています。
