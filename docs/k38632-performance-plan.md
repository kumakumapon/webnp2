# KDESK描画負荷とXARRAY32の検証計画

対象はMS-DOSの `tools/k38632/PERFORMANCE-PLAN.md`。現行版の基準はMS-DOS
f1589e072cf32d92821e4fdd9641a3b884559bf5、WebNP2
ea764c78bf0e4f1d123d2b002892f1b2c6d11c18です。開発計画と検証手順を記録します。

- 改善前の同梱イメージで、時計の重なり描画とPM32/V86の進行、入力応答、
  FILE32/VIEW32の完了を計測する。時計を閉じず、同じクロック・RAM・表示条件で比較する。
- 描画負荷を減らし、安全な実行管理の復帰地点を検証する。割り込み内でDOSを呼ばない。
- XARRAY32.EXEを同梱する。既存XARRAYと同じデータ・2 MiB処理・8192個の16ビット値の
  ソート・境界検索を検証し、結果とCPU時間、経過時間、API呼び出し数を区別して記録する。
- 実CPU・世代・私有データ・停止再開・例外回収・低メモリ時の元所有者保持と
  全ディスク不変性をPEGC/CirrusのPlaywrightで確認する。
- npm test/buildと既存の全回帰CIを維持する。ネイティブSHAを固定し、生成ディスクは
  CI成果物にする。既存のライセンスとソースの由来を維持する。

共有2スロット、PM32各4 MiB、読み取り専用ファイルAPIを維持します。新GUI部品API、
共有書き込み、スロット増加はこの変更に含めません。測定前に改善倍率を約束しません。
検証条件・結果・未完了項目をドラフトPRへ記録し、全部成功してからReadyにします。
マージ順はMS-DOS側、main CI成功確認、WebNP2側です。自動マージは行いません。

## 実装と計測方法

MS-DOS側の詳細は `tools/k38632/ARRAY32.md` にあります。時計盤とDOS出力の
変更部分を裏画面に描き、手前のウィンドウの実ピクセルと文字・属性を保護してから
表示します。スケジューラの再入や割り込み内DOS呼び出しは追加しません。
16色、モーダルUI、ドラッグ中、重なったスクロールバー変更では従来の合成に戻ります。

`XARRAY32.EXE` は既存ABI0101hの起動・ヒープ・入力機能だけを使用します。
1〜5で個別実行、Aで全件、Hで2 MiB保持、Cで保持データ再検証、Qで終了、
Fで回収検証用のページ例外です。引数1/2で別のデータを保持できます。
PM32のfillは32ビット単位で同じバイト列を読み書きします。V86のキャッシュ付き
バイト操作と命令数まで同一とはしません。両者の仕事量はバイト数・要素アクセス数です。

```sh
bash scripts/prepare-msdos4-cpanel-ci.sh
npm ci
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort --base /webnp2/
# 別のターミナル。CHROMIUMで使用するブラウザを指定できます。
node scripts/measure-k386-render-load.mjs http://127.0.0.1:4173/webnp2/ test-results/render changed pegc
node scripts/verify-k38632-array.mjs http://127.0.0.1:4173/webnp2/ test-results/array pegc
# cirrus に置き換えて両スクリプトを再実行。
```

描画計測は各3回、16 MiB、clk=8、worklet=0。FILE32は起動から終了まで、VIEW32は
キー送信から次/前ページ待機までを測ります。CPU/service ticks・実行回数・SVC回数と
ホスト経過時間を分離し、相手のCPUカウンター・世代・CR3・物理領域も確認します。
文字情報だけの成功判定にせず、重なり・端数ピクセル移動・非表示/復元時の可視ピクセル、
TVRAM文字・属性、全シーン合成回数も検査します。時計を閉じて性能条件を回避しません。

配列検証はホスト側の独立した参照計算と、V86/PM32双方の実結果を照合します。
別CR3/ページマッピング、2 MiBデータ保持・停止再開、Endと例外後の相手の全データ
再検証、通常終了、4 MiB設定での実XMS不足拒否、所有資源回収、全ディスクハッシュを
検査します。ページ内の配列終端チェックはアプリ側の範囲検査であり、ハードウェアが
任意のバイト境界を保護するとは説明しません。

ベースラインは旧版の生成済みdist/manifest/イメージを別ポートで固定してから、
`measure-k386-render-load.mjs <旧版URL> <保存先> baseline <表示モード>` で測ります。
旧版には新しいGUI診断レコードがないため、共通の実CPU進行・仕事量を基準にします。
ベースラインのタイムアウトは未完了として記録し、成功値として扱いません。
実行時のブラウザ、イメージSHA、ソースSHA/dirty、設定、各試行値はJSON成果物に残ります。
この時間はブラウザのCPU使用率でも、任意のアプリの速度保証でもありません。

CIでは `k38632-render-load (pegc/cirrus)` と `k38632-array (pegc/cirrus)` が
固定コミットから生成した同じイメージを検証します。既存の回帰ジョブも維持します。
最終測定結果・最新CIの成功確認は両PRに記録し、全条件の完了までドラフトを維持します。
